## 浏览器上传

在**文件**页面，你可以使用**上传文件**、**上传文件夹**，或者直接把文件拖放到浏览器窗口的任意位置。使用**后台上传**则可将任务交给服务端 worker 处理——参见[后台上传](#后台上传)。

## 可续传上传

```yaml
uploads:
  session-ttl: 168h
```

上传中断后，只要会话仍然有效即可续传；会话创建后，其分片在 `session-ttl` 期间内保持可认领状态。

## 分片大小

分片大小由服务器决定，而不是客户端：

- 未指定分片大小的会话使用 `uploads.default-part-size`（默认 `512MiB`）；
- 指定了分片大小的会话，如果超过 `uploads.max-part-size`（默认 `4GiB`）则会被**拒绝**；
- `max-part-size` 必须不小于 `default-part-size`，且必须是它的整数倍。

浏览器用户可在**设置 → 上传**中设置*首选*分片大小；但服务器仍可能选择其他值。在小型主机上请优先调低 `default-part-size`：较小的分片重试代价更低，且每个并发上传占用的内存更少。

## 哈希校验

```yaml
uploads:
  hashing-enabled: true
```

Teldrive 默认计算 BLAKE3 哈希。只有在经过实测的性能理由下才应关闭它——并注意，关闭此项只会跳过**服务端**哈希计算。客户端提交的校验和始终会被验证，因此传输损坏依然能够被发现。

## 分片级重试

`(uploadId, partNo)` 是分片的幂等键。重新发送内容完全相同的分片时，服务器会以 `200` 返回已存储的分片，而不会再次写入；如果分片的大小或校验和不同，则以 `409` 拒绝。因此，重试失败的分片始终是安全的——客户端应当重试，而不是从头开始。

请将该分片的校验和通过 `X-Part-Checksum`（小写十六进制）发送。它是该分片的 BLAKE3 **树哈希**——与文件哈希同一套方案，按 16 MiB 分块计算——**不是**对该分片字节做一次扁平 BLAKE3。只有当分片不超过 16 MiB 时两者才一致；使用随附的 `512MiB` 默认分片大小时，扁平 BLAKE3 会在每个分片上被以 `422 hash_mismatch` 拒绝。

上传分片使用 `PUT /api/v1/uploads/{uploadId}/parts/{partNo}`，请求需带 `Content-Type: application/octet-stream` 以及准确的 `Content-Length`。

## 后台上传

**文件 → 后台上传**会把任务排入队列交给 worker 处理，而不是占用你的浏览器。添加一个或多个来源，然后点击**加入上传队列**；进度会显示在**任务**中。

每个来源属于以下两种之一：

- **HTTP URL** —— 由服务器通过 HTTP(S) 抓取，可选自定义请求头。**无需任何配置**，但目标主机必须解析到**公网** IP：私有、回环、链路本地等非公网地址会以 `HTTP target has no public address` 拒绝；跨主机的重定向会剥离 `Authorization`、`Cookie` 与 `Proxy-Authorization`。
- **本地路径** —— 服务器上的绝对路径，递归读取。需要 **admin 或 owner 角色**，*并且*至少配置一个 `uploads.local-import-roots` 条目（见下文）。非管理员在任务入队时就会收到 `403`，而不是等到 worker 执行时才失败。

每个来源可以设置目标子路径和排除规则；针对整批任务可以设置最小/最大体积、并发分片数、分块大小和加密。

## 从本地路径后台导入

除非至少配置了一个根目录，否则本地来源处于禁用状态：

```yaml
uploads:
  local-import-roots:
    - /srv/imports
```

**空列表会彻底禁用本地导入** —— 含本地来源的作业会以 `local imports are disabled` 失败。开箱即用的只有 HTTP 来源。

容器挂载：

```yaml
volumes:
  - /srv/imports:/srv/imports:ro
```

导入根目录是一条安全边界；只应暴露 Teldrive 需要读取的目录。路径必须是绝对路径，并且源路径和每个根目录在比较之前都会先解析符号链接，因此植入根目录内部的链接无法越界访问。

## Telegram 并发数

```yaml
telegram:
  upload-threads: 8
```

在监控吞吐量和 Telegram 错误的同时，逐步调高该值。

## 进度与失败

浏览器传输显示在上传界面中；后台导入显示在**任务**中。

遇到失败时，请检查 Telegram 会话/频道可用性、PostgreSQL、代理超时、导入路径/挂载权限、会话过期时间以及并发设置。

参见[上传与事件](/configuration/uploads-and-events)。
