**任务**页面展示 River/RiverPro 后台作业，例如服务端导入以及 bot/频道维护。

## 状态

一个作业恰好处于以下八种状态之一：**待处理**、**可用**、**已调度**、**运行中**、**可重试**、**已取消**、**已丢弃**或**已完成**。

并不存在“失败”状态。**可重试**表示 River 会按自己的退避策略再次尝试；**已丢弃**表示它已用尽尝试次数并停止——当某项功能彻底损坏时，就该查看这一状态。

在网页界面中只能按状态筛选——作业 API 还接受 `type` 与 `queue` 过滤参数，但任务页面只发送 `status`。搜索框匹配作业的 ID、类型、队列、消息或输出。重试已丢弃或可重试的任务之前，请先打开它——详情视图会显示每一次尝试及其错误和时间戳。只有在修复了诸如路径无效、凭据被吊销、权限缺失或配置错误这类永久性原因之后，才重试由暂时性原因导致的失败。

## 创建与清理

**新建任务**可以加入队列的只有各类维护清理作业：上传会话清理、事件清理、回收站清理、待处理文件清除，以及孤儿 Telegram 数据清理。上传批次与 bot 供应不在其中——它们由各自的流程创建，作业 API 会以 `422` 拒绝它们。队列与优先级字段是自由文本输入。**清理**则清除指定状态的已完成作业。两者都在任务工具栏上，且都需要 admin 或 owner 角色。清除只会删除任务记录，绝不会撤销它们已完成的工作——删除一个导入任务并不会删除它所导入的文件。

## 取消

在支持取消的情况下，取消会停止后续处理；但它不会撤销已经完成的外部副作用。在作业详情页中，作业处于待处理、已调度、可用、运行中或可重试状态时才提供取消操作；在列表页中，只有运行中的作业显示取消按钮，其余活动状态显示的是删除按钮，而它同样会取消该作业。

## 暂停队列

在任务页面打开**队列**，你可以在排空某条流水线或执行 Telegram 维护时暂停一个队列。被暂停的队列不再分发新任务；已排队的作业仍留在队列中，并在原处继续，而已经在运行的作业不会被打断。

Teldrive 恰好只为两个队列注册了 worker：

| 队列 | 工作内容 |
| --- | --- |
| `uploads` | 后台导入批次和单文件导入 |
| `maintenance` | bot 供应、回收站/会话/孤儿数据清理、事件清理、待处理文件清除 |

队列名在入口处不做校验：**新建任务**允许管理员输入任意其他队列名，这类队列会出现在队列面板中，但永远没有 worker 消费，因此放入其中的作业不会被处理。

暂停 `maintenance` 不会暂停上传，反之亦然。暂停操作需要 admin 或 owner 角色。

参见[作业与队列](/operations/jobs-and-queues)。

## 周期性作业

**设置 → 周期性作业**中保存着持久化的调度（清理和清除扫描）。该部分仅对拥有 `system.maintenance` 权限的用户——管理员和所有者——显示。其他用户完全看不到它，也无法直接调用周期性作业 API。

## Worker 配置

默认值：

```yaml
jobs:
  run-workers: true
```

仅当由其他进程运行 worker 时，才在纯 API 实例上将其设为 `false`。

参见[作业与队列](/operations/jobs-and-queues)和[多实例部署](/advanced/multi-instance)。
