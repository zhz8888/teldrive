---
title: 首次登录与验证
description: 在投入生产使用之前，先验证登录、数据持久化、上传与下载是否正常。
---

## 1. 登录

打开界面并使用 Telegram 登录。登录页面提供两种方式：

- **二维码** —— 选择二维码标签页，用已登录设备上的 Telegram 扫码并确认。服务器所在主机不需要手机号，也不会收到短信。
- **手机号** —— 输入 E.164 格式的号码，**通过短信接收验证码**；如果你的账号设置了两步验证，还需要填写两步验证密码。Teldrive 不指定任何投递方式，也不会请求 Telegram 把验证码发送到已登录的应用会话中。

两种方式都会把 Telegram 会话用 `security.data-key` 加密后存储，因此请保持该值稳定并做好备份。一旦修改，已存储的会话将无法解密。

## 2. 确认你的角色

**第一个**完成登录的 Telegram 账号会成为**所有者**。之后登录的所有账号角色都是 `user`。所有者无法被降级，也无法被撤销权限，因此请先用你希望拥有该实例所有权的账号登录。

其他账号可在**设置 → 用户与角色**中提升。在把 Teldrive 暴露到公网之前，先用 `security.allowed-users` 限制哪些人有权登录 —— 详见[限制登录](/deployment/production)。

## 3. 测试存储

新建一个文件夹，上传一个小文件，然后再把它下载下来。这一步会同时验证 API、Telegram 存储链路和 PostgreSQL 元数据。

## 4. 重启 Teldrive

```bash
docker compose restart teldrive
```

重新加载界面，确认账号、文件列表和下载仍然正常。

## 5. 重启 PostgreSQL

```bash
docker compose restart postgres
```

等 PostgreSQL 恢复健康后，再确认一次同样的数据。如果这里失败，通常说明数据库存储没有持久化，或者密钥发生了变化。

## 6. 查看日志

```bash
docker compose logs --tail=200 teldrive
```

排查反复出现的数据库、迁移、认证或 Telegram 重连错误。

## 开放公网访问之前

请完成[生产环境检查清单](/deployment/production)：HTTPS、访问限制、备份、可信代理以及锁定版本。
