---
title: Reverse proxy and HTTPS
description: Put Teldrive behind a TLS reverse proxy without breaking cookies, uploads, or SSE.
---

Keep Teldrive private and terminate TLS at the proxy:

```text
browser ──HTTPS──► proxy ──HTTP/private network──► Teldrive :8080
```

## Trusted proxies

Trust only the address/CIDR of the proxy that connects directly to Teldrive:

```yaml
http:
  trusted-proxies:
    - 127.0.0.1
```

Teldrive believes forwarding headers only from a peer listed here; for every other peer the headers are ignored and the connection peer is used instead. Do not use `0.0.0.0/0` or `::/0`.

This one setting decides three things:

- **Cookie `Secure` flag.** `X-Forwarded-Proto: https` from a trusted peer marks the request secure, which is what makes session cookies `Secure`. Misconfigure it and the browser gets non-`Secure` cookies over HTTPS, or login appears to loop.
- **CSRF origin check.** State-changing cookie-authenticated requests are accepted only when `Origin` matches the request host *and* the scheme Teldrive resolved. A wrong scheme yields `403 csrf_rejected`.
- **Request-log client address.** Only for trusted peers is the last `X-Forwarded-For` entry recorded instead of the socket peer.

## Routes that need proxy care

| Route | Method | Why |
| --- | --- | --- |
| `GET /v1/events` | SSE | Long-lived `text/event-stream`; needs `proxy_buffering off` and a read timeout above `events.heartbeat`. |
| `PUT /v1/uploads/{uploadId}/parts/{partNo}` | Upload | Carries a full file part; needs no body-size limit and streamed request bodies. |
| `GET /health/live`, `GET /health/ready` | Probe | Unauthenticated; keep them reachable from the proxy for load-balancer checks. |

## Caddy

Same host:

```text
drive.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

```yaml
http:
  address: 127.0.0.1:8080
  trusted-proxies:
    - 127.0.0.1
```

For containerized Caddy, trust the actual container-network source CIDR instead.

## nginx

```nginx
server {
    listen 443 ssl;
    server_name drive.example.com;

    ssl_certificate     /etc/letsencrypt/live/drive.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/drive.example.com/privkey.pem;

    client_max_body_size 0;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_request_buffering off;
        proxy_buffering off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

The event stream authenticates browsers with a short-lived `ticket` query parameter, because `EventSource` cannot send an `Authorization` header. The default nginx `access_log` records the full request line including that parameter. Treat proxy access logs as secrets, or strip the parameter before logging:

```nginx
# in the http block
log_format teldrive '$remote_addr - $remote_user [$time_local] '
                    '"$request_method $uri $server_protocol" $status $body_bytes_sent';

access_log /var/log/nginx/teldrive.access.log teldrive;
```

`$uri` excludes the query string, so the ticket never reaches the log.

## Timeouts

Teldrive's own defaults are `http.read-header-timeout: 10s`, `http.read-timeout: 1h`, `http.write-timeout: 1h` and `http.idle-timeout: 2m`. The `3600s` values above match the 1h read/write defaults; raise them together with `http.read-timeout` / `http.write-timeout` when you raise the proxy values.

Two rules the defaults imply:

- `proxy_read_timeout` must stay above `events.heartbeat` (default `20s`). Teldrive writes a keep-alive comment on that interval, so a proxy timeout at or below it tears down an idle event stream.
- Setting `http.read-timeout: 0` and `http.write-timeout: 0` disables the server-side limits entirely for streaming transfers. Do that before raising the proxy timeouts for very large files; otherwise the 1h server limit truncates a transfer the proxy was configured to allow.

During a restart or deploy, in-flight requests get at most `http.shutdown-timeout` (default `10s`). Set it above your proxy's drain window if you rely on long uploads completing across a rollout.

## Container binding

```yaml
services:
  teldrive:
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      TELDRIVE_HTTP_ADDRESS: 0.0.0.0:8080
      TELDRIVE_HTTP_TRUSTED_PROXIES: 172.18.0.0/16
```

Replace the example CIDR with the network your proxy actually uses.

## Verify

After enabling HTTPS, test:

- login and page refresh;
- upload/download;
- live task/progress updates;
- no repeated SSE reconnects or cookie errors.

If a CDN/load balancer sits in front of your proxy, Teldrive should still trust only its direct proxy peer; that proxy must sanitize forwarding headers.
