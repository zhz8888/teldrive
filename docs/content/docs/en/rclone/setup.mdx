## Status of the native backend

Teldrive's README advertises a native `teldrive` rclone backend, but **this repository ships no rclone backend**: there is no rclone module in `go.mod`, no backend source under `internal/`, and no rclone binary or plugin in the release archives. `rclone config` will not offer a `teldrive` type unless you obtained the backend separately.

Treat every backend option as unverified until you can read `rclone help backend teldrive` for the build you actually have. What follows is the surface that *is* real and versioned by this project: the HTTP API.

## 1. Create an API key

In Teldrive, open **Settings → API keys**, create a key, and copy the secret. It is shown once — the server stores only a hash.

## 2. Drive the API directly

Teldrive serves its API under `/api` (also reachable as `/v1`). Authenticate with
`Authorization: Bearer <API key>`.

There is no configuration snippet to paste here: a remote definition needs a backend that
exists in your rclone build, and this repository ships none. Until one is available, drive the
API directly with `curl` or any HTTP client — the table below is the whole surface.

## What the API offers

The generated contract in the [API Reference](/api/) is authoritative. The operations an rclone-style backend needs:

| Operation | Request |
| --- | --- |
| List / search | `GET /api/v1/files?parentId=&path=&search=&searchType=&category=&sort=&order=` |
| Create folder | `POST /api/v1/folders` |
| Resumable upload | `POST /api/v1/uploads` → `PUT /api/v1/uploads/{uploadId}/parts/{partNo}` → `POST /api/v1/uploads/{uploadId}/complete` |
| Download | `GET /api/v1/files/{fileId}/content/{fileName}` with `Range` |
| Copy / move | `POST /api/v1/files/{fileId}/copy`, `POST /api/v1/files/{fileId}/move` |
| Trash / restore / delete forever | `DELETE /api/v1/files/{fileId}`, `POST /api/v1/files/{fileId}/restore`, `DELETE /api/v1/files/{fileId}/purge` |

Use `If-Match` / `If-None-Match` for optimistic concurrency control, and the `ETag` and `Location` headers returned by create/complete operations.

## Trash operations

Trash lives behind ordinary REST calls, not backend commands:

| Action | Request |
| --- | --- |
| Move to trash | `DELETE /api/v1/files/{fileId}` |
| Restore | `POST /api/v1/files/{fileId}/restore` |
| Delete permanently | `DELETE /api/v1/files/{fileId}/purge` |
| Empty the whole Trash | `DELETE /api/v1/files/trash` |

Permanent deletion cannot be undone, and emptied Trash is reclaimed asynchronously by the pending-file purge maintenance job.

## Test

```bash
curl -fsS -H "Authorization: Bearer $TELDRIVE_API_KEY" \
  https://drive.example.com/api/v1/files
```

Revoke exposed or retired keys from **Settings → API keys**.
