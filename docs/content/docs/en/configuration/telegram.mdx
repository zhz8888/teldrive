Teldrive includes public Telegram application credentials. Override `app-id` and `app-hash` only when using a custom Telegram application.

## Connection

```yaml
telegram:
  backend: remote
  dial-timeout: 10s
  reconnect-timeout: 5m
  max-retries: 10
  rate-limit: true
  rate-interval: 50ms
  rate-burst: 10
```

Keep rate limiting enabled unless you have a specific reason to change it.

## Uploads

```yaml
telegram:
  upload-threads: 8
```

Valid range: `1`–`32`. Increase only after measuring throughput and Telegram errors.

## Downloads

```yaml
telegram:
  download-bots: 0
  download-client-pool: false
  download-read-buffers: 32
  download-read-parallel: 4
```

- `download-bots`: `0` sends every download through the authenticated user account; `1`–`32` caps how many of the user's **already enabled** bots take part in download rotation. It does not enable bots — add and enable them first (see [Bots](/using/bots)) — and it does not limit uploads, which always rotate across every eligible enabled bot.
- `download-client-pool`: keeps authenticated download clients warm between HTTP requests instead of building one per request. It holds `max(1, download-bots)` Telegram clients open for the lifetime of the process, so it trades persistent Telegram sessions for lower per-request latency. Leave it `false` (the shipped default and what both config samples recommend) unless you have measured the per-request client setup cost.
- `download-read-buffers`: prefetched 1 MiB chunks held in memory per open range, range `1`–`256`.
- `download-read-parallel`: concurrent chunk fetches per range (and the number of Telegram connections requested per range), range `1`–`32`.

Memory and connections both scale with these settings. Each open download range buffers up to `download-read-buffers` 1 MiB Telegram chunks, and up to `download-read-parallel` of them are fetched concurrently. Multiplied by [`uploads.max-concurrent-downloads`](/configuration/uploads-and-events), the buffer count is the process download-memory ceiling: the defaults are 4 × 32 = 128 MB. Change one without the other only trades throughput for memory. See [Performance tuning](/advanced/performance).

## Storage channels

```yaml
telegram:
  randomize-part-names: true
  auto-channel-create: true
  channel-part-limit: 500000
  channel-name-prefix: teldrive
```

See [Storage channels](/using/channels).

## Bot rotation

```yaml
telegram:
  bot-rotation-backend: memory
```

Use `memory` for one instance and `database` when multiple instances must coordinate bot rotation.

## Proxy

Standard HTTP/HTTPS/SOCKS5 proxy:

```yaml
telegram:
  proxy: "socks5://user:password@proxy.example.com:1080"
```

MTProxy:

```yaml
telegram:
  mtproxy:
    address: "proxy.example.com:443"
    secret: "YOUR_SECRET"
```

Do not configure both. MTProxy address and secret must be set together.

## Client logging

```yaml
telegram:
  client-logging: false
```

Enable temporarily for low-level Telegram diagnostics.

## Filesystem backend

For development/tests only:

```yaml
telegram:
  backend: filesystem
  local-root: ./var/local-telegram
```

This stores payloads locally instead of in Telegram, and none of the gotd settings above it — `upload-threads`, `download-bots`, `download-read-*`, `proxy`, `mtproxy`, `client-logging`, `channel-part-limit`, `bot-rotation-backend`, and the device-identity keys — are applied in this mode.
